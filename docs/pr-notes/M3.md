# M3 PR notes

## Summary

- Adds read-only Google Calendar authentication and incremental event retrieval through the controlled HTTP client.
- Parses Handoff Review bookings from a synthetic redacted captured-shape fixture.
- Adds one guarded Zoho workflow using `(google_calendar, event_id, sync_booking)` and budgets of 10 per run and 100 per UTC day.
- Matches Contacts before Leads; updates the booking timestamp and creates marker-deduplicated Note/Task records, or email-upserts a Lead when no record exists.

## Safety

- Booking sync remains disabled by default and `DRY_RUN` remains true.
- Dry run records the intended skipped write and performs zero Google or Zoho HTTP when the validated booking is injected into the guarded workflow.
- Calendar access is read-only; no Google SDK bypasses the egress client.
- Reschedules and cancellations are detected but deliberately deferred with no cursor advance because the approved idempotency key covers only the initial booking action.
- All committed fixtures use synthetic identities and ids. No production credentials or rows are included.

## Protected change

`src/tis/http.py` and `scripts/guard.py` add exactly `oauth2.googleapis.com` and `www.googleapis.com`, preserving NET004 parity.
